Factory Method
In this section, we will explore how Factory Method works in Rust. We'll see how Rust's
approach to constructors and its powerful type system often provide alternatives that are more

How does Factory Method work in Rust?
In object-oriented languages, Factory Method encapsulates object creation, hiding
instantiation logic and often enabling subclass customization. This is typically achieved
through inheritance and virtual methods. Rust doesn't have classes or inheritance, so the
pattern adapts: instead of virtual methods that subclasses override, Rust uses associated
functions (methods without self) that return concrete types. The encapsulation benefit
remains. Callers don't need to know the construction details, but the polymorphism comes
from enums and traits rather than inheritance hierarchies.
idx_35c1d835
Let's see how this manifests in our Correct Calculator project, where we need to create
different kinds of tokens to represent numbers, operators, and functions in our expressions.
In an object-oriented language, we might create a Token class hierarchy with factory methods
for each type. In Rust, we can take a more natural approach. Rather than creating a complex
class hierarchy, we'll use Rust's enums (which provide sum type functionality) to represent our
different token types. This approach leverages Rust's pattern-matching capabilities and gives
us type safety without inheritance. We'll define our tokens as enum variants, with each variant
holding the appropriate data for that token type. Then, we'll add constructor methods that act
as our factory methods, providing a clean API for creating tokens while encapsulating any
validation logic that we need.107

•Concrete subclasses such as NumberToken and OperatorToken
•A TokenFactory class with methods that return the base Token type

traditional factory methods. They simply look like constructors for enum variants. However,

Let's see how we might approach this. First, we will need to define some traits for our different
token types. For the Abstract Factory pattern, we'll use Rust's trait system to define interfaces

Unlike object-oriented languages, where we'd create abstract base classes, Rust's traits provide
a more flexible way to define shared behavior. We'll create traits that specify what operations
numbers and operators must support, then implement these traits for different calculator
modes.
Traits combined with associated types allow us to ensure that all tokens from a given factory
work together correctly. This gives us compile-time guarantees that we can't mix incompatible
token types.

used during expression evaluation. Higher values mean the operator should be evaluated first.

returning either a result or an error message for cases such as division by zero.

make refactoring easier. If you need to change how binary operations are structured, you only
need to update one method.
